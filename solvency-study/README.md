# solvency-study

Skill to analyze documentary solvency for rental applicants.

## What it does

- Scans documents from a folder or the whole project.
- Extracts data from PDFs and images.
- Cross-links evidence across documents.
- Runs public company checks when useful.
- Generates a markdown report with traffic-light risk status.
- Supports incremental mode to avoid reprocessing unchanged files.

## Easy mode (recommended)

You can start with a minimal prompt. If required parameters are missing, the skill asks for them in a short guided flow.

Example minimal prompt:

Use solvency-study for Carlos and Ariadna in Las Marinas contracts folder.

The skill will ask only what is missing, typically:

- Scope (`project` or `folder`).
- Folder path (if scope is `folder`).
- Incremental options (`incremental_mode`, `force_full_rescan`).
- Output language.

Defaults if you do not specify values:

- `report_language: auto`
- `incremental_mode: true`
- `force_full_rescan: false`

Incremental continuity key behavior:

- Auto-derived from scope path (or workspace root in project mode).
- No `subject_id` question is required.
- If you explicitly provide `subject_id`, it is used as override.

Before execution, the skill shows the resolved configuration and asks for one confirmation.

## Output

- Full report: `solvency_report_{subject}_{YYYY-MM-DD}.md`

Output rules:

- Only one user-facing report is generated (full report).
- User-facing section headings are localized to the selected report language.
- Technical metadata is placed at the end of the file in a code block.
- Reorganization dry-run/audit standalone files are not generated by default.
- Separate reorganization files are created only if explicitly requested by the user.

## Folder reorganization language

- If reorganization is requested, folder names should follow the user's output language.
- In existing structures, preserve the dominant naming language already used in that folder tree.

## Language behavior

- Skill instructions are in English.
- Report output language is controlled by `report_language` in the technical metadata block.
- Default is `auto`:
	- Prompt language first.
	- Local machine language second.
	- Fallback to English.
